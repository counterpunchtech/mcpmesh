# 0.49.0 design — a resume signal (#167 ask 2)

Version: **0.48.0 → 0.49.0 (MINOR)**. `API_MINOR` 54 → 55.

---

## The gap

> **Is there a resume/suspend signal an embedder can hook, so an app can tear down and re-dial
> deliberately rather than discover it on the next send?**

#167 asks three things. Two were answered in 0.40.0 by documenting them: `open_session` does not
re-establish (the client sees EOF), and `subscribe` terminates with the connection and does not
replay. This is the third, and it is the only one that needs code.

Today an embedder learns its session died by **trying to use it**. For a messaging app holding one
session per peer across a closed laptop lid — the reporter's steady state, not an edge case — that
means the failure surfaces when the user sends a message, which is the worst possible moment.

## Why a suspend is detectable at all

Rust's `Instant` is `CLOCK_MONOTONIC` on Linux and `mach_absolute_time` on macOS, and **neither
advances while the machine is suspended**. The wall clock does.

So a ticker that measures both deltas tells the two apart:

| | monotonic Δ | wall-clock Δ |
|---|---|---|
| normal tick | ≈ period | ≈ period |
| **suspend/resume** | ≈ period | **≫ period** |
| CPU starvation / a stalled runtime | ≫ period | ≫ period |

A suspend is precisely "wall clock advanced far more than monotonic did". That distinction is what
keeps a loaded machine from emitting a false resume — which matters, because this repo has twice
produced confident-and-wrong diagnoses from single timing samples, and a signal that cried wolf
under load would be worse than none.

## What ships

A `StreamFrame::Resumed { suspended_secs, at_epoch }` on `subscribe`.

- Emitted **once per resume**, when the wall-clock delta exceeds the monotonic delta by more than a
  threshold.
- `suspended_secs` is the gap the machine was away — the number an embedder actually wants, because
  it decides whether to re-dial everything or nothing.
- Not retroactive: a subscriber that connects after a resume does not see it. This is a transition
  signal, like `Reachability` and `SelfNetwork`, and the snapshot answers "what is true now".

**It says nothing about any particular session.** It cannot: the daemon does not know which of an
embedder's sessions still work, and a peer's connection may well have survived a short suspend. The
frame means "this machine was away for N seconds; check what you hold", which is exactly the
deliberate teardown-and-re-dial the issue asks for.

### Threshold

`RESUME_THRESHOLD_SECS = 10`, against a 2s tick.

Above the tick by enough that ordinary scheduling jitter, a slow fsync, or a busy runtime cannot
reach it; well below the 30s default idle timeout, so the signal arrives for suspends that actually
kill sessions. A 3-second lid close does not fire, and nothing was lost either.

### It also refreshes what it can

On resume the daemon **clears the reachability cache**, so the next `status` re-probes rather than
serving pre-suspend verdicts. Without that, an embedder acting on the resume frame reads a peer list
describing the world as it was before lunch. The existing `reachability_of` refresh path does the
work; this only invalidates.

## What this deliberately does NOT do

- **No transparent resumption.** `open_session` still does not re-establish, and 0.40.0's docs say
  so. Making it transparent means owning retry policy, backoff and idempotency on behalf of every
  embedder — a much larger change the issue does not ask for.
- **No replay.** `subscribe` still does not replay missed events; the frame tells you that you
  missed some, which is the honest half.
- **No suspend (pre-sleep) signal.** A process gets no reliable warning before suspension on either
  platform without OS-specific hooks; promising one would be a lie.

## Testing

1. **The detector is pure and exhaustively tested**: a normal tick emits nothing; a wall-clock jump
   with a normal monotonic delta emits; a jump in BOTH (CPU starvation) emits nothing; the threshold
   boundary is pinned from both sides.
2. **The frame reaches a subscriber** end to end, through the real control socket.
3. **The reachability cache is invalidated** on resume, so a stale verdict cannot survive it.
4. **Wire shape**: tagged `resumed`, round-trips, and an older payload without it still parses.

### Mutations to run

- the monotonic delta ignored (wall-clock only) → the starvation test fails.
- the threshold comparison inverted or removed → the normal-tick test fails.
- the cache invalidation dropped → the staleness test fails.
- the frame built but never sent → the end-to-end test fails.
