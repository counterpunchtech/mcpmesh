# 0.39.0 design — embedder seams (#67, #85 ask 1)

Two capability gaps an embedder cannot work around from outside. Both are `mcpmesh-node` API only:
no control verbs, no `api_minor` bump.

Version: **0.38.0 → 0.39.0 (MINOR)** — new public items in `mcpmesh-node` and `mcpmesh-trust`.

---

## #67 — no seam for a custom ALPN

The set of protocols a node speaks was fixed at build time (`boot.rs`'s `alpns_for`), and the accept
loop dispatched on a closed match over it. `Node` exposed no endpoint, no registration, no handler
hook.

mcpmesh has already built the hard parts of a P2P application platform — identity, pairing, a trust
gate, relay fallback, discovery, rate limiting, a connection registry — and exposed **one** protocol
shape on top: request/response MCP over bi-streams. Anything else (realtime media wanting datagrams,
bulk transfer, an app-level overlay) was out of reach however well the identity layer suited it. The
only alternative was a second endpoint with a second identity, discarding the gate, the pairing
relationship and the relay config, and making users pair twice.

### The seam

```rust
impl Node {
    pub fn accept_protocol(&self, alpn: &[u8], handler: Arc<dyn iroh::protocol::DynProtocolHandler>)
        -> anyhow::Result<()>;
    pub async fn connect_protocol(&self, peer: &str, alpn: &[u8])
        -> anyhow::Result<iroh::endpoint::Connection>;
    pub fn endpoint_addr(&self) -> iroh::EndpointAddr;
}
```

`DynProtocolHandler` rather than `ProtocolHandler`: the latter uses RPITIT and is not object-safe.
iroh provides a blanket impl, so an embedder writes the ergonomic trait and passes an `Arc`.

**The client half is not optional.** The issue asked only for registration, but a server handler with
no way to dial is unusable, and an embedder holding "alice" has no way to turn that into an address.
`connect_protocol` reuses `open_session`'s resolution (nickname / `b64u:` user_id / `eid:`) plus the
stored dial-address hint — which is most of what this is worth over a raw endpoint.

### Where it hooks in

The accept loop's ALPN match gains an arm **after** every built-in, consulting
`MeshState::app_protocols`. On a hit it runs the same `gate_and_register` as the MCP and blob arms,
then the handler.

That is the whole value: the custom protocol inherits authorization, the connection registry, and
severing on revocation. The `Registration` is held for the handler's life, so revoking a peer cuts
it **mid-protocol**.

### Reserved namespace

`register_app_protocol` refuses an empty ALPN and anything starting with `mcpmesh/`. The registry is
consulted only for ALPNs the built-in arms do not own, so a handler on `mcpmesh/mcp/1` would be
silently dead — and one on a name mcpmesh adds *later* would flip from working to dead on an
upgrade. Refusing the namespace makes both impossible. `app/…` is documented as the convention (the
issue suggested requiring it; refusing `mcpmesh/` is the safety property, requiring `app/` is
style).

### Runtime registration

`Endpoint::set_alpns` exists in iroh 1.0.3, so registration rebinds the advertised set live rather
than being builder-only. `rebind_alpns` recomputes the built-ins from `alpns_for` and appends the
registered ones — `set_alpns` REPLACES the whole set, and appending to a stale list is how an
endpoint quietly stops answering its own protocols.

Documented limit: ALPN is chosen at handshake, so registration affects connections negotiated from
then on.

### `iroh` re-exported from `mcpmesh-node`

These signatures name iroh types, so an embedder needs them in scope; requiring a `mcpmesh-net`
dependency for that is friction. Same rule as the existing re-export: never add your own `iroh`.

## #85 ask 1 — no key-source seam

The device key is 32 raw ed25519 secret bytes at 0600 in a directory the node owns. No passphrase,
no keychain, no hardware seam — and an embedder could not fix it from outside, because the file is
inside the mesh root it is told not to hand-write and nothing accepted a decrypted key at boot.

```rust
NodeBuilder::new(root).device_key(signing_key)
```

Threaded through a new `BootOverrides` struct rather than as another `boot_node` parameter:
`boot_node` backs both `serve_forever` and `NodeBuilder::start`, so every parameter added is one the
daemon shell must thread through and keep meaningless. `DeviceKey::from_signing_key` wraps a caller's
key without touching disk.

**When set, no key file is read, minted, or written.** The `match` replaces `load_or_generate`
entirely rather than falling back to it — a fallback would boot happily under a *different* identity
if the supplied key were somehow absent, leaving every paired peer unable to reach the node with
nothing saying why.

Custody moves to the caller: no escrow, no recovery (#85 asks 2–3, not shipped), and it is the
identity every peer pinned at pairing.

### Not in this release

- **#85 (2)** `user_key_export` / `user_key_import` with a recovery phrase.
- **#85 (3)** a device attestation so a peer admits a replacement device without a fresh SAS.
- **#85 (4)** a pairing-mode revocation list.

Ask 1 is the one the issue itself calls "a large win alone", and it is the one that needs no new
wire format or trust rule. The rest each change what peers must accept from each other.

## Testing

Both through **two real embedded nodes**, since the value of each is wiring the unit tests cannot
see.

**#67**, one test with two halves:

1. A PAIRED peer reaches the handler, which sees its authenticated `EndpointId`, and the payload
   round-trips.
2. An **unpaired** peer does not reach it at all.

Half 2 is the load-bearing one and its first version was **vacuous**, caught by mutation: node B
dialled by `eid:` before pairing, which never reached A — no stored address, no discovery on a
hermetic mesh, so the dial died locally and `calls == 0` regardless of the gate. Deleting
`gate_and_register` left it green. Rewritten to use a **bare iroh endpoint** dialling A's real
`endpoint_addr()`, so a stranger completes a handshake and negotiates the ALPN, and the gate is the
only thing that can stop it. The test now panics if the stranger fails to *reach* A, so the vacuity
cannot silently return.

Also asserted: the `mcpmesh/` namespace and empty ALPN are refused.

Mutations caught: gate deleted; namespace guard removed; `rebind_alpns` dropping the built-ins;
`set_alpns` never called.

**#85 ask 1**: the identity is the supplied key; **no `device.key` is written**; it is stable across
a restart with the same key; and — the control that stops the fix being "never write a key file" —
a node with no supplied key still mints its own.

Mutations caught: supplied key ignored; supplied key used but the file still minted.
